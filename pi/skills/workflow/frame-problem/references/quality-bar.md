# Quality Bar: Problem Framing

A high-quality `Problem.md` must pass these checks:

1. **The "So What?" Check**: Does the "Why it matters" section explain the cost of inaction?
2. **The "Measurability" Check**: Is there at least one concrete success criterion? (e.g., "Build passes", "Feature X is visible", "Latency is reduced").
3. **The "Scope" Check**: Are the Non-Goals clearly stated to prevent scope creep?
4. **The "Honesty" Check**: Are unknowns correctly moved to "Open Questions" rather than glossed over?
5. **The "Actionability" Check**: Is the title a description of a state to be achieved, not just a noun? (e.g., "Fix auth race condition" vs "Auth issue").
